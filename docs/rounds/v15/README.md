## 背景：为什么这 40 条是一轮

阶段一的一次全库通读与阶段二的逐条复现暴露的共同模式，与 v12 §0.5 的
"多份实现各自漂移 / 元数据存在但消费者没查"两个元模式同族，本轮新增
第三个模式：**"判定式缺一个反向分支"**——同一处代码对 Integer 与 Float、
对有无 INFO/AC,AN、对单块与跨块，只覆盖了其中一条分支，另一条静默走错：

1. **类型分支只写对一半**：基因型掩码的 Float 列分支（D15-1）与
   Integer 分支差一个运算符；oracle 的 PBS/f2 与 shipped 差一整套口径
   （D15-12、D15-31）。
2. **cohort 变化只清了一半**：`--mind`/子集清了 `info_trusted`，掩码与
   `--set-gts .` 没清（D15-2），而编译期门与 shadow 早已知道 cohort 变了。
3. **边界形态只覆盖常见侧**：BCF 头恰落块边界（D15-3）、窗口末位重复
   POS 跨接缝（D15-19）、多头之后的窗口（D15-20）、接缝两侧同 POS ——
   每条都是"另一侧没测过"。
4. **校验存在但没接线**：`--proj` 上限、pop 文件重复分配、contig 改名
   撞名、`-o` 缺失的检查顺序、`-o -` 的字面量——校验函数都有先例
   （v12 D12-11/12 同款），就是没在这条路径上调用。
5. **性能形状在数据形态变化时翻转**：`SiteKeepSet` 线性扫（D15-17）、
   `--rm-dup-ids` 双重 deflate（D15-28）、convert 全矩阵驻留（D15-7）。

修复判据沿用项目纪律：**每条修复必须附带能失败的回归测试**（阶段二
证明现有测试套件对 15 条必须修全部失明：`-q/-Q` 零 e2e、Float 掩码零
夹具、窗口重叠零用例、搬迁重定向只测了 1/27），证据与缺口见 01 §6。
