## 组织原则：补丁下沉

本轮的每个条目不是"再加一个修复"，而是"把一类补丁从调用点收回底层"。判据：
同一语义 ≥2 处实现（P1）、调用点 guard 代替 API（P2）、同一修法重复 N 次（P3）、
不变式靠人肉同步（P4）、死链路/恒常量输出（P5）——满足任一条即下沉候选。
动作只有四种：Sink / Delete / Keep + 等价性测试 / Verify + 常驻门。每条验收必须
回答 00 §6 的"补丁复发测试"四问。**本轮不做**的重复（oracle、text/BCF 双 reader、
per-pair 累积、word kernel）在 01 §4.3 登记，保留条件是等价性测试。

**结构因果**：18 组判定（20 个文件）中 9 组判"乱"、8/9 乱组与补丁热点重合（08）。但文件
混杂本身不是 bug——它产生"语义多入口"，多入口让补丁只能打在调用点，才产生
bug。所以拆分只作为**语义下沉的载体**，顺序固定为：语义收口 → 拆分（纯搬家）
→ 常驻门；不单开"美化轮"。
