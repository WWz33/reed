| 维度 | 结论 |
|---|---|
| v5 完成度 | X0–X3、X4.1–X4.4、X6（部分）、X7 落地；未做：前后端三项收尾、`job.rs` 拆分、C-5、联合 SFS、`--bed-file/--sites-file`、LD kb 窗口对齐 |
| 工程 | 产品路径绿（382 测试、守卫 23、gold PASS）；**CI lint 门红**（2 doc lint + 测试 pedantic）；文档漂移 8 处；死代码若干；发布脚本剔除 docs/bench。目录树合格、fmt 干净、lint/unsafe/profile 策略成熟；**发布层面不像可交付项目**：声明了 `MIT OR Apache-2.0` 却无 LICENSE 文件、无 tag/CHANGELOG/安装说明、`--version` 无构建信息；`pixy` 词汇在生产模块与公开项；8 个文件 > 600 行（05 §7） |
| 架构 | 并行骨架正确且在极限（filter 效率 96%）；错在把全局分析塞进串行归约点；`-Ob`/BCF 输入文本往返；三套 pass0 与两套发射闭包重复；引擎四处健壮性 |

| 模型 | `GtCode`/位平面/计数三表示维持，不转 2 位规范（半调用语义）；**位平面矩阵成为全局分析的规范输入**；统计模型全部对拍过，偏差已登记；两个 `ContigId` 要合一 |
| 正确性 | 流式 chunk 源偏移漂移（潜伏）、abort 容量/许可泄漏（挂起类）、计数内核 release 不健全（无调用者）、顺序模式未实现 |

## 本轮的裁决依据（无新裁决）

延续：CLI 产品、前后端形态、不做 Python 绑定、不做多等位、`--geno/--mind` 原样、`--fst-global`、LD 剪枝一条命令。本轮没有改变任何用户裁决。

## 需要你确认

| 项 | 推荐 | 备选 |
|---|---|---|
| 矩阵模式的内存策略（Y1） | 估计 `位点数 × 192 B` 进 `--memory`；超预算按 contig 分段；全基因组 348 样本 ≈ 634 MB | 永远按 contig 分段（更省内存，剪枝并行度不变，衰减跨 contig 无影响） |
| deflate 默认级别 | 保持 6（与 htslib 行为同族），文档给出 4 级数字（CPU −20%、体积 +7%）供用户选 | 默认改 4 |
| 计数内核（F6-5） | **删除** SIMD 路径与 `CountTable`（计数 < 5% CPU，且 348 样本永不向量化） | 修 soundness + 填充到 8 字保留 |
| 顺序模式（F6-6） | 实现 `run_sequential`（小机器与调试有用，代码量小） | 改规范删承诺 |
| `-Ob` 记录模型范围（Y4） | 只在 `-Ob` 与 BCF 输入路径启用，`-Oz` 文本输出保持字节级编辑 | 全路径统一记录模型（更干净，但 `-Oz` 会变慢） |
| 公开树（E6-8） | 公开 `docs/spec/`（规范本身不含内部数据），`docs/rounds/` 与 `bench/` 继续不公开 | 维持全部不公开，CI 拆两套 |
